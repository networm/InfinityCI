## 三平台打包脚本（含 ARM64，Pascal 命名）

### 产物（`publish/dist/`，Pascal 命名，server 与 agent 分包，共 10 个）
- `InfinityCI.Server.Win64.zip` / `InfinityCI.Agent.Win64.zip`
- `InfinityCI.Server.Linux64.tar.gz` / `InfinityCI.Agent.Linux64.tar.gz`
- `InfinityCI.Server.LinuxArm64.tar.gz` / `InfinityCI.Agent.LinuxArm64.tar.gz`
- `InfinityCI.Server.Osx64.tar.gz` / `InfinityCI.Agent.Osx64.tar.gz`
- `InfinityCI.Server.OsxArm64.tar.gz` / `InfinityCI.Agent.OsxArm64.tar.gz`

包内布局（server 为例，脚本同样 Pascal 命名）：
- `InfinityCI.Server.exe`（自包含单文件）+ 运行所需文件
- `wwwroot/`（Web 界面）
- `appsettings.json`（发布输出自带）
- `StartServer.cmd`（win）/ `StartServer.sh`（unix，tar 保留执行权限）
- agent 包：`InfinityCI.Agent.exe` + `StartAgent.cmd|.sh` + appsettings.json

### 一、小改（零配置产物）
`CiServerOptions`/`Program.cs`：Web 静态目录自动探测——发布布局下存在 `wwwroot/` 时自动使用，否则维持开发布局 `../../web/dist`。

### 二、打包脚本 `scripts/publish-all.cmd` + `scripts/publish-all.sh`
1. **Web 构建**：`web/` 下 `npm ci && npm run build`。
2. **RID 循环**（win-x64、linux-x64、linux-arm64、osx-x64、osx-arm64）：`dotnet publish -c Release -r {rid} --self-contained -p:PublishSingleFile=true`（server 加 `-p:IncludeNativeLibrariesForSelfExtract=true`）→ 输出 `publish/{rid}/server|agent`。
3. **组包**：`web/dist` → server 的 `wwwroot/`；生成 Pascal 命名的启动脚本（server：设 `InfinityCI__ListenHost=0.0.0.0` 后运行；agent：透传参数连接 master）。
4. **压缩**：win-x64 → `.zip`（Compress-Archive）；其余 → `.tar.gz`。
5. 附带说明：Linux 系统依赖（git、libldap）、macOS 首次运行解除 Gatekeeper 隔离。

### 三、验证
本机 dotnet 交叉发布与压缩可行——实际执行脚本全流程：产出 10 个压缩包、解压 win-x64 server 冒烟（/health + 页面）、检查 unix 包执行权限。提交脚本与 wwwroot 探测小改。
