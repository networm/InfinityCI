## 任务本地目录（运行时状态，不进 YAML）

### 设计
- 目录配置存 `WorkflowState` 运行时状态（与启用状态、通知渠道同类，独立于配置 Git 仓），YAML 完全不感知——为将来「从工作目录直接读取 YAML 配置」留路。
- 语义：本地执行的 job 以该目录为工作目录（SCM 检出与步骤都在其中）；绝对路径原样使用，相对路径相对服务器数据目录；目录不存在自动创建；留空 = 默认按次隔离目录；agent job 不经过本地执行器，天然不受影响。
- 迁移 v8→v9：`WorkflowStates` 加 `WorkspaceDir TEXT`。

### 改动清单
1. **存储/迁移**（`Entities.cs` / `DbMigrator.cs`）：`WorkflowState.WorkspaceDir`；v9 迁移步骤。
2. **服务**（`WorkflowControlService.cs`）：`GetWorkspaceDirAsync` / `SetWorkspaceDirAsync`；`WorkflowRuntimeState` 增加 `WorkspaceDir`（state 接口一并返回）。
3. **API**（`CiApi.cs`）：`PUT /api/jobs/{name}/workspace`（body `{ workspaceDir }`，空串清除，Admins 权限）。
4. **执行**（`RunQueueService.cs` / `JobRunExecutor.cs`）：本地执行链路从 control 服务读取覆盖值传入 executor；executor 解析路径（相对拼 DataDir）、自动建目录，目录创建失败置 job Failed 并写 `[server]` 日志；生效时追加 `[server] working directory override: <路径>` 日志。
5. **前端**（`job-editor.tsx` / `api.ts` / `types.ts` / i18n）：编辑页表单模式下、名称输入框正下方新增「本地目录」输入框（占位符 + 灰色说明）；随「保存」按钮一并提交（新建任务先创建工作流再设置目录）；zh/en 文案。
6. **测试**：控制服务 Set/Get roundtrip 单测；集成测试——API 设置目录后触发运行，断言运行成功、日志含 override 行、自定义目录真实创建。

### 验证
`dotnet build + test`、`npm run typecheck + build`、重启 Server 浏览器确认编辑页字段并实际触发运行验证目录生效，分批提交。
