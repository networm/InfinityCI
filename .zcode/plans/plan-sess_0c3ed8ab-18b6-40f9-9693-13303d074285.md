## 服务器 Docker 化 + 打包脚本

### 前置代码改动（容器内必须）
`Program.cs` 目前硬编码 `ListenLocalhost(5000/5001)`，容器内外部无法访问。改为可配置监听地址：
- `CiServerOptions` 新增 `ListenHost`（默认 `"127.0.0.1"`，本地行为完全不变）；
- `ConfigureKestrel` 用 `options.Listen(ListenHost, 5000/5001)`；容器/远程部署时设 `InfinityCI__ListenHost=0.0.0.0`。

### Docker 产物（仓库根目录）
1. **`Dockerfile`**（多阶段）：
   - stage 1 `node:22-alpine`：`npm ci && npm run build` 产出 `web/dist`；
   - stage 2 `mcr.microsoft.com/dotnet/sdk:10.0`：`dotnet publish src/InfinityCI.Server -c Release -o /app/publish`（global.json 为 rollForward=latestFeature，镜像 SDK 满足）；
   - stage 3 `mcr.microsoft.com/dotnet/aspnet:10.0`：装 `git`（SCM 检出用 git CLI）与 `tzdata`（cron 时区）；拷贝 publish → `/app`、web/dist → `/app/wwwroot`；环境变量 `InfinityCI__WebDistDir=wwwroot`、`InfinityCI__DataDir=/app/data`、`InfinityCI__ListenHost=0.0.0.0`；EXPOSE 5000/5001；创建非 root 用户 `ci` 并授权 `/app/data`；`ENTRYPOINT dotnet InfinityCI.Server.dll`。
2. **`.dockerignore`**：排除 `bin/ obj/ node_modules/ web/dist/ data/ publish/ .git/` 等（dist 在镜像内重建）。
3. **`docker-compose.yml`**：端口 `5000:5000`、`5001:5001`，命名卷持久化 `/app/data`（SQLite+配置仓+日志），示例环境变量 `TZ`、`InfinityCI__PublicOrigin`。
4. **打包脚本**：`scripts/docker-build.ps1` 与 `scripts/docker-build.sh`（与本仓库脚本风格一致）——参数化镜像名/标签（默认 `infinityci-server:latest`，支持 `-Tag`/`--tag` 传多标签），执行 `docker build`。

### 说明
- 仅服务器容器化；Agent 保持宿主机运行（其价值正是访问宿主机本地目录，容器化会破坏该场景）。
- 容器内本地 job 用 `/bin/sh` 执行（基础镜像自带）；数据全部落在挂载卷，升级镜像不丢数据。
- 首次启动仍种子 admin/admin，启动后应改密。

### 验证
`dotnet build/test` 回归（ListenHost 改动）+ `npm build`；若本机 docker 可用：`docker build` 成功 → `docker run` 冒烟（/health 探活、页面可访问、数据卷生成）→ 产出运行说明；若本机无 docker，交付脚本与使用说明并注明未实测。
