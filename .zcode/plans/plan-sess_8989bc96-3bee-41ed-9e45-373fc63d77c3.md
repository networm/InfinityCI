# Infinity CI — 最终技术方案（.NET 10 类 Jenkins CI 服务器）

## 核心架构约束：每个网页是独立实时客户端

- 每个标签页创建自己独立的 SignalR HubConnection，服务器端各有独立 ConnectionId；Cookie 认证共享登录态，连接与订阅各 tab 独立；Kestrel 启用 HTTP/2。
- 服务器按组广播 `dashboard` / `job-{id}` / `build-{id}` / `agents`；tab 在看哪个构建就只加入哪个组；断开自动清理订阅。
- REST 拉历史 + SignalR 推增量；日志每行带单调字节偏移量（offset），重连带 offset 续传，不丢不重；状态变更带版本号。
- 按连接游标 tail 日志，单 tab 高频日志不拖慢其他页；推送限速 + 前端按帧批量渲染。

## 后端（C# / .NET 10）

- ASP.NET Core Minimal API + SignalR；Generic Host 宿主；Serilog；Data Protection 加密凭据
- 自研流水线调度（Channel/Dataflow）+ Quartz.NET 定时；EF Core + SQLite（可切 PostgreSQL），日志存文件、DB 存元数据
- YAML 流水线定义（YamlDotNet）；LibGit2Sharp + GitHub/GitLab webhook
- 插件系统 V1 暂缓，只留内置扩展点接口

## 前端（React + Rsbuild + shadcn/ui）

- React 19 + TypeScript；Rsbuild（Rspack/Rust 构建，替代 Vite）
- shadcn/ui（Radix + Tailwind CSS，组件源码入库）；TanStack Router / Query / Table；react-hook-form + zod
- Zustand（tab 内状态）；@microsoft/signalr（每 tab 一实例）；xterm.js 日志终端；React Flow DAG
- 产物打包进 wwwroot，与后端合并为单一 EXE 分发

## Agent 设计（按最佳实践）

- **反向连接**：Agent 主动 gRPC 连接 Master（双向流），Token 注册/认证（注册 token 换 agent token）；指数退避自动重连
- **心跳租约**：Agent 周期心跳，Master 超时标记离线；租约失效时其运行中的构建标记失败/重排队，绝不永久卡 Running
- **拉取式分发**：Agent 声明空闲 → Master 下发一个任务（pull 语义）；Agent 上报标签（windows/dotnet/docker 等）+ 最大并发数，Job 声明所需标签，调度器 label 匹配
- **日志链路**：Agent 批量上报日志块（100ms/64KB flush）带 buildId + offset，Master 校验连续性 → 落盘 → 推 SignalR 组，Agent→浏览器一条 offset 链贯通
- **安全**：秘密运行时注入环境变量/临时文件，两端日志脱敏（mask secret 值）；构建即任意代码，默认与 Master 分机部署
- **工作区卫生**：每构建独立工作区 + clean checkout 策略选项；后续支持 Docker per build 隔离
- **运维**：drain 平滑下线（不派新活、跑完退出）；版本握手（Agent 上报版本，与 Master 不匹配提示/自动更新）；提供 Windows Service / systemd 安装；Agent 周期上报 CPU/内存/磁盘 → 实时面板

## 开发工作流（本次执行约定）

1. 先 `git init`（当前目录尚非 git 仓库）
2. **每完成一个功能必须提交**：功能实现 + 适用处单元测试 + Chrome 浏览器实测通过后，一次 Conventional Commits 提交
3. **Chrome MCP 验证**：前端功能用浏览器实操验证（导航/点击/填表/截图核对）；多标签页独立性通过多开页面实测；验证不通过不提交

## 实施步骤（每步 = 一个功能 = 一次提交）

1. 脚手架：Server / Agent / Core / Web 四项目 + git 初始化 + CI 脚本
2. Job 模型与 YAML 解析（Core）
3. 构建队列与进程执行引擎 + 日志落盘（带 offset）（Server）
4. SignalR Hub：分组订阅 + offset 续传协议（Server）
5. REST API：jobs / builds / logs 分页（Server）
6. 前端框架搭建：Rsbuild + shadcn/ui + 路由 + SignalR 客户端（每 tab 独立连接、自动重连续传）
7. 前端页面：构建列表页（dashboard 实时刷新）+ 构建详情页（xterm.js 实时日志）——Chrome MCP 验收
8. **多标签页独立性实测**：3 个 tab 跟踪不同构建，验证互不串扰、关 tab 无影响、重连续传——Chrome MCP 验收
9. Agent：注册/心跳租约/拉取式分发/日志上报（gRPC）+ Agent 管理页
10. 后续迭代：Quartz 定时、webhook 触发、凭据管理与日志脱敏、DAG 可视化、容器执行、drain/自动升级
