## 1. 用户姓名（DisplayName）

**后端**
- `User` 实体加 `DisplayName`（可空，展示时回退 Username）；种子 admin → DisplayName=「管理员」；Schema 变更 → 删开发库重建（老流程，Agent 需重新注册令牌）
- `/api/users` CRUD 增加 displayName；`/api/me` 返回 displayName
- 新端点 `GET /api/users/names`（任意登录用户）→ `{ username: displayName }` 映射，供前端全局解析
- Git 配置提交：`CommitAll` 的 author 改传操作者 DisplayName（历史提交保持不变）

**前端**
- `useUserNames()` 一次性加载映射，提供 `resolve(username)`；所有显示用户名的地方改用它：
  - Runs 列表「触发人」列、任务详情运行历史、Run 详情「由 X 触发」
  - 顶栏当前用户（显示 姓名，悬停/括号保留用户名）
  - 用户管理页：表单加「姓名」输入、列表加姓名列
- Dashboard 提交作者：新提交自然带姓名（历史提交不变）

## 2. 参数化构建

**YAML**（可选块）：
```yaml
params:
  ENV_NAME: production          # 简写：名称: 默认值
  VERSION:
    default: "1.0"              # 完整形式
    required: true
    description: 构建版本
```
- Core：`WorkflowParam {Name, Default, Required, Description}` + `Workflow.Params`；解析两种形式、校验名称合法（字母数字下划线）
- **触发**：`POST /api/jobs/{name}/trigger` 接受 `{ params: {...} }`；required 缺失且无默认 → 400；最终值 = 用户填的值 ∪ 默认值，序列化存 `Run.ParamsJson`（新列）
- **执行**：所有参数以**参数名即环境变量名**注入进程（顺序：workflow env → 参数 → step env），本地与 Agent 一致；`JobAssignment` 增加 `params_json` 字段下发给 Agent
- **前端**：Run 按钮 → 若有参数弹「参数化构建」对话框（默认值预填、required 标红、description 提示）→ 带值触发；Run 详情头部显示本次使用的参数 chips；无参数任务行为不变

## 3+4. Jenkins 圆形任务图 + 开始/结束结点

- `lib/dag.ts` 重构布局输出：圆形结点（r≈14）+ 文字在圆下方居中；新增虚拟 **Start**（最左层，连向所有根 Job）与 **End**（最右层，来自所有无下游 Job）结点
- Start = 灰色圆；End = 按当前 Run 状态着色（绿/红/琥珀）；Job 圆形描边用状态色、选中高亮蓝不变
- 点击行为不变（Start/End 不可点）；`DagView` 渲染改为 circle + text，行距加大避让文字

## 5. 日志下载

- 后端 `GET /api/runs/{runId}/logs/{jobKey}/download?format=raw|timestamped`：
  - `raw`：仅日志文本，每行一条
  - `timestamped`：`yyyy-MM-dd HH:mm:ss.fff  文本`（本地时区）
  - `Content-Disposition: attachment`，文件名 `{workflow}-{runId}-{jobKey}[.timestamped].log`
- 前端 Run 详情 Job 头部加「下载」下拉：原始日志 / 带时间戳日志（同源 anchor 下载，Cookie 随请求）
