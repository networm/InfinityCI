# Infinity CI v2 — GitHub Actions 风格重构 + 并行任务 + 权限系统

## 1. 执行模型重构（GitHub Actions 语义）

**YAML v2**（旧单 job 格式自动兼容包装为单 job）：
```yaml
name: demo
project: Default          # 所属项目，缺省 Default
jobs:                     # 多个 job 并行执行
  build:
    runs_on: local        # local | agent | agent:<label>（标签匹配）
    steps:
      - name: Build
        command: dotnet build
  test:
    runs_on: agent:docker
    steps: [...]
```

**新模型链**：`Workflow（YAML 定义）→ Run（一次触发）→ JobRun（并行单元，每个 job 一个）→ Steps`
- 并行：触发即创建 N 个 JobRun，local 的进本地工作池（全局 MaxConcurrentJobs 控并发），agent 的进待领取队列（标签匹配）；同一 Run 的多个 JobRun 同时执行。
- Run 状态聚合：任一 JobRun Failed → Failed；全部终态后收敛；取消级联到所有 JobRun（本地 CTS / Agent 取消消息 / 队列项校验）。

## 2. 日志 v2：每 Job 独立 JSONL + 逐行时间戳

- 路径 `logs/{runId}/{jobKey}.jsonl`，每行 `{"o":字节偏移,"t":"UTC时间戳","s":步骤索引,"m":"内容"}`。
- **时间戳由 Master 统一写入**（本地与远程 Agent 时钟一致，Agent 不传时间）。
- SignalR：`logAppended(runId, jobKey, line)`、`jobUpdated(jobRun)`、`runUpdated(run)`；`SubscribeRun(runId)` 返回快照+全量日志，重连重放 + 客户端按 offset 去重（多标签页 `run-{id}` 组隔离模型保留）。

## 3. 用户权限系统

- 表：`Users`（PBKDF2-SHA256 密码哈希，角色 **SuperAdmin / Admin / User**）、`Projects`、`UserProjects`（用户↔可见项目）。
- **Cookie 认证**（登录/登出/`GET /api/me`），SignalR 复用 Cookie；API 返回 401 由前端跳登录页。
- 权限矩阵：SuperAdmin → 全部 + 用户管理；Admin → 全部项目 + 任务/Agent 管理；User → 仅被授权项目（查看 + 触发）。任务列表按可见项目过滤。
- 首次启动种子：`admin/admin`（超管）+ `Default` 项目。

## 4. API

- `/api/auth/login|logout`、`/api/me`
- `/api/users` CRUD（超管，含角色 + 可见项目设置）、`/api/projects` CRUD（管理员）
- `/api/jobs`：列表（按可见项目过滤）、创建/修改/删除（管理员，写 YAML 文件热加载）、`trigger`
- `/api/runs`：列表/详情/取消
- `/api/agents`：在线列表 + 持久注册表（启用/禁用/删除）+ **注册令牌签发**（ enrollment token，注册时校验，一次性）

## 5. Agent 协议适配（proto）

- `JobAssignment{run_id, job_key, job_yaml}`、`LogChunk{run_id, job_key, step_index, offset, text}`、`StepUpdate`/`JobFinished` 同构；`AgentRegistration` 增加 `enroll_token`。

## 6. 前端（GitHub Actions 风格，参照所给链接）

- **登录页**（未登录时全屏，登录后进入主布局）
- 顶栏导航：Runs / 任务 / Agents / 管理（按角色显示）
- **Runs 列表页**：GH Actions 表格风（状态图标、Run 编号、工作流名、触发人、耗时）
- **Run 详情页（核心页面）**：
  - 左侧并行 Job 侧栏：全部 JobRun 的实时状态图标 + 名称 + 过滤框
  - 主区：Job 头部（状态/名称/时长）+ **每个步骤独立可折叠 Console 段**（状态图标 + 步骤名 + 耗时；默认展开，可收起）
  - 日志行 = `时间戳列 + 内容`（时间戳灰色等宽），暗色控制台（#0d1117），自动滚动
- **任务创建/编辑页**：多 Job 结构编辑器（Job 分组、步骤行增删改、runs_on 选择、环境变量），js-yaml 客户端往返 + YAML 文本模式切换，保存走服务端校验
- **用户管理页**（超管）：用户表、新建/编辑（角色、密码重置、可见项目勾选）、删除
- **项目管理页**（管理员）：项目 CRUD
- **Agent 管理页**：在线状态表（现有）+ 注册令牌签发（显示一键启动命令行）+ 持久注册表启用/禁用/删除

## 7. 迁移与验证

- Schema 变更 → 删除旧开发库重建；旧示例 YAML 升级为 v2 并行格式
- 工作流：每功能一次提交；单测覆盖 YAML v2 / 并行聚合 / 权限；Chrome 端到端验收：登录 → 触发并行 Run（多 Job 同时跑、每步独立 Console、逐行时间戳）→ 普通用户项目隔离 → 任务创建/编辑 → 用户管理 → Agent 注册令牌 + 禁用

## 实施顺序（每步一提交）

1. Core：Workflow/Run/JobRun 模型 + YAML v2 + 测试
2. Server：并行引擎 + JSONL 日志 + Hub/API 重写 + Agent 协议适配
3. Server：认证/用户/项目/令牌 + 种子 + 任务 CRUD
4. Web：登录 + 布局 + Runs 列表 + Run 详情页（GH 风格）
5. Web：任务编辑器 + 用户/项目/Agent 管理页
6. 端到端 Chrome 验收 + 旧数据迁移清理
