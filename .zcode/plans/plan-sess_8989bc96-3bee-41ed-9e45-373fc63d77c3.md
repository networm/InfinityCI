# 任务详情页：工作流级 Run 历史 + 分页

## 现状
- 后端 `GET /api/runs` 支持skip/take 分页但**不能按工作流过滤**；`RunRepository.ListRunsAsync` 无 workflow 参数、无总数查询。
- 前端 `/jobs` 是任务列表页，任务名没有详情入口；`/runs` 页的实时刷新模式（dashboard SignalR 组 + REST 快照）已可直接复用。

## 方案

### 1. 后端（一个新端点 + 仓储扩展）
- `RunRepository`：`ListRunsAsync` 增加 `workflowName` 可选过滤；新增 `CountRunsAsync(workflowName)` 返回总数（分页 UI 需要）。
- 新端点：`GET /api/jobs/{name}/runs?skip=0&take=20`
  - 返回 `{ total, items: RunsPageItem[] }`（Run + 并行 JobRun 列表，与 /api/runs 同构）
  - 鉴权：登录即可查；先做项目可见性检查（不可见 → 404，与 CanSeeWorkflowAsync 一致）
- 单测：分页正确性（total/条数/页边界）+ 可见性过滤 + workflow 过滤。

### 2. 前端（新路由 `/jobs/$name` → WorkflowDetailPage）
- **头部卡片**：任务名、项目、Job 列表（key + runs_on + needs 徽章，复用 JobsPage 样式）、操作按钮：Run / 编辑 / 历史（复用 HistoryDrawer）/ 删除（管理员）。
- **Run 历史表**（GitHub Actions 风）：
  - 服务端分页：每页 20 条，「上一页 / 第 x / y 页 / 下一页」+ 总数显示；空态提示
  - 列：状态图标（Run 级 + 各并行 Job 级，复用 StatusIcon）、Run 链接（→ /runs/$id）、触发人、创建时间、耗时
  - **实时更新**：订阅既有 dashboard SignalR 组，按 workflowName 过滤，仅就地更新当前页内的行（runUpdated/jobUpdated），翻页/进页拉 REST 快照 —— 与 Runs 列表页同一套模式，多标签页隔离模型不受影响
- **入口**：JobsPage 的任务名改为 Link → `/jobs/$name`。

### 3. 验证与提交
- 单测跑全量；Chrome 端到端：任务列表点进详情 → 分页翻页 → 触发一次 Run 实时出现在列表 → 历史抽屉可用。
- 每功能一次提交（后端端点 + 前端页面可各一笔或合并一笔）。
