# Git SCM 集成 + Jenkins 风格首页 + 收藏

## 1. SCM 集成（Git 检出）

**工作流 YAML 新增 `scm` 块**（可选；配置了则每个 Job 的步骤在检出后的源码中执行）：
```yaml
name: demo
scm:
  url: https://github.com/octo/repo.git    # https / 本地路径（file/路径）/ SSH
  branch: main                              # 可选，默认远端默认分支
  ref: v1.2                                 # 可选，显式 tag/commit，优先于 branch
  credentials: my-cred                      # 可选，命名凭据引用
```

- **实现**：LibGit2Sharp（Server 已引用，移到 Core 共用）→ 新 `GitSourceFetcher`：目录为空则 Clone，已存在则 Fetch + 强制 Checkout（branch 或 ref）；检出行输出到 Job 日志（`[server] checked out <sha> on <branch>`）。
- **凭据**：新 `StoredCredential` 表（名称 + 用户名 + Data Protection 加密密文），管理 API（管理员增删查列表，永不回显密钥）；`scm.credentials` 按名引用。
- **本地执行器**：步骤前检出 → `JobRun` 新列 `SourceBranch` / `CommitSha` 落库。
- **Agent 执行器**：Master 在 `JobAssignment` 下发解析后的 scm 信息（url/branch/ref + 已解密凭据，仅限内网/TLS 场景），Agent 用同一 GitSourceFetcher 检出，并通过新 proto 消息 `ScmCheckout{branch, commit_sha}` 回报落库。
- **测试**：本地临时 Git 仓库端到端（init→commit→工作流 scm 指向本地路径→Run→工作区含源文件且记录 commit sha）；凭据 API 测试。

## 2. 首页 Jenkins Blue Ocean 风格 + 收藏

- **实体**：`UserFavorite(UserId, WorkflowName)` 唯一索引；`POST /api/jobs/{name}/favorite` toggle。
- **聚合端点 `GET /api/dashboard`**（按可见项目过滤）：
  `[{ name, project, jobs[], isFavorite, branch, commit{sha,message,author,when}, lastRun{id,status,createdAt,startedAt,finishedAt,triggeredBy} }]`
  - branch/commit 优先取**最近一次 Run 的 SCM 检出信息**（真实源码分支/提交）；无 SCM 的任务回退到配置仓库的分支/最近提交。
- **首页 `/` 改版**（参照 Jenkins Blue Ocean dashboard）：
  - **收藏区置顶** + 全部任务区；**一行一任务**
  - 行内：状态图标（最新 Run 状态，运行中转圈）→ ★收藏按钮 → **任务名链接到 `/jobs/$name`** → 分支徽章 + 最近提交（短SHA+说明+作者）→ 右侧最后构建（#编号/状态/时间/耗时）→ Run 按钮
  - **整行状态背景色** + 左侧粗色条：绿=Success、红=Failed、琥珀动画=Running、灰=Queued/从未运行
  - 实时更新：dashboard SignalR 组就地刷新行状态与最后构建信息
- 「最近 Runs」表保留在页面下方。
