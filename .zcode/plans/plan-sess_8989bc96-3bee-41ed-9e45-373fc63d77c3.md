# Infinity CI v3 — needs 依赖图 + Git 配置仓库 + 运行脚本

## 1. 运行脚本

- `scripts/start-server.cmd`：构建并启动 Server（5000 Web / 5001 gRPC）
- `scripts/start-agent.cmd [args]`：启动 Agent，参数透传（`--Agent:EnrollToken=… --Agent:AgentName=…`）
- `scripts/publish.cmd`：发布 Server/Agent 单文件 EXE 到 `publish/`
- 同名 `.sh` 版本；README 补充使用说明（含 .NET 10 SDK、注册令牌流程）

## 2. Job 依赖（needs）——形成 DAG

**YAML v3**（GitHub 语义）：
```yaml
jobs:
  build:        { steps: [...] }
  test:
    needs: [build]
    runs_on: agent
    steps: [...]
  deploy:
    needs: [build, test]
    steps: [...]
```
- `WorkflowYaml.Parse` 校验：needs 引用的 job 必须存在、禁止环（DFS 检测），违规报错（保存与触发都被拦截）。
- **调度**：触发时仅入队无 needs 的 JobRun（依赖未满足的保持 Queued）；每个 `JobRun` 持久化 `NeedsJson`。
- 终态分派（集中在 RunQueueService 的新方法，本地与远程完成后都调用）：
  - JobRun **Success** → 依赖它的 JobRun 若 needs 全部 Success 则入队（本地/Agent 按需）
  - JobRun **Failed/Cancelled** → 直接+传递依赖标记为 **Skipped**（GH 默认语义，无 if: always()）
  - 之后统一 `RunAggregator.RecomputeAsync`（Skipped 视为终态，不导致失败；任一 Failed → Run Failed）
- `JobRun.IsTerminal` 与状态扩展加入 Skipped；前端状态图标加 Skipped。
- 任务编辑器：每个 Job 增加「依赖 (needs)」多选（候选=其他 Job Key），保存时服务端再校验。

## 3. DAG 可视化（主区顶部图形 + 下方详情）

- Run 详情页：当工作流任一 Job 有 needs 时，主区顶部渲染 **SVG 依赖图**（分层布局：层=最长路径，层内车道分布；节点=状态图标+JobKey，肘形连线=needs 边；GitHub 配色 #d1d9e0 线、节点可点击、选中高亮）。无依赖时保留现状。
- 点击节点 → 下方切换该 Job 的头部 + 每步独立 Console（现有组件复用）；运行中节点实时状态（jobUpdated 驱动）。
- 布局算法为前端纯函数（`lib/dag.ts`），含环不可能出现（服务端已拦截）。

## 4. 任务配置 Git 仓库（服务端自建）

- 新包 **LibGit2Sharp**；`data/jobs` 首启自动 `git init`（已有 YAML 成为初始提交），默认身份 "Infinity CI <ci@localhost>"。
- **自动提交**：每次 Save/Delete 工作流 → commit（message 如 `update workflow demo` / `delete workflow demo`，author=操作用户名），无变更则跳过；commit 后重写 `.git/info/refs`（dumb HTTP clone 支持）。
- **历史/回滚 API**（Admins）：
  - `GET /api/jobs/{name}/history` → [{sha, message, author, when}]
  - `GET /api/jobs/{name}/blob/{sha}` → 该版本 YAML
  - `POST /api/jobs/{name}/restore` {sha} → 以旧内容 Save（生成新提交，不改写历史）
- **只读克隆**：`git clone http://user:pass@host:5000/git/jobs` —— `/git/jobs/info/refs`、`/HEAD`、`/objects/**` 端点以 Basic Auth（校验 Users 表）映射到 `data/jobs/.git` 物理文件。
- **UI**：任务列表/编辑页增加「历史」入口 → 抽屉：提交列表 → 查看该版 YAML → 「恢复此版本」。

## 5. 测试与验收

- 单测：needs 校验（未知引用/成环）、依赖链顺序执行、失败→下游 Skipped 且 Run=Failed、历史/回滚 API。
