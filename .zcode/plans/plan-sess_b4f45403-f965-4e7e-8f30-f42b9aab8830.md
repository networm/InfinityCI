# Infinity CI 翻译补全方案（修订版）

**词汇表（用户指定）**：Dashboard→总览、Runs→构建、Agents→节点、Run→运行、Job→任务。
**衍生约定**：单数 Agent→节点；Token/YAML/Shell/Webhook 等纯技术词保留英文；CPU 保留。zh 中 workflow 与 job 统一为「任务」（遵循现有用法，如 nav.jobs=任务）。

## 1. 后端按所选语言返回消息（新增机制）

**前端** `web\src\lib\api.ts`：在统一的 `request()` 封装（第 21-24 行）中给 fetch 加请求头 `Accept-Language: i18n.language`（"zh" 或 "en"，来自 i18n/index.ts 当前语言），后续切换语言自动生效。

**后端**：
- `src\InfinityCI.Core` 新增轻量助手 `Msg.T(string en, string zh)`：按 `CultureInfo.CurrentUICulture` 是否为 zh 返回对应文案（两参数内联，无需 resx 资源文件）。
- `src\InfinityCI.Server\Program.cs`：管线早期加 `app.UseRequestLocalization(...)`（SupportedUICultures = en/zh，默认 zh），从 Accept-Language 头自动设置请求文化；启动时设 `CultureInfo.DefaultThreadCurrentUICulture = zh`，保证后台线程（运行执行、Git 拉取）有确定语言（默认中文）。
- 约 30 条消息改为双语，插值标识符保留在两种语言文本中（如 `Msg.T($"Job '{key}' needs unknown job '{need}'.", $"任务「{key}」依赖了不存在的任务「{need}」。")`）。
  - **CiApi.cs**：所有 `new { message = ... }` 字面量（项目/用户/任务/凭据/Webhook 等 17 条，含两处 "does not exist. Create it on the Projects page first."）
  - **WorkflowYaml.cs**：8 条校验消息（Invalid YAML、缺少 name、必须定义 jobs、Job 为空/自依赖/未知依赖/依赖循环、参数名非法）；zh 用「任务」；保留 name/command 字样满足测试断言
  - **RunQueueService.cs**：缺少必填参数 1 条
  - **GitSourceFetcher.cs**：5 条 Git 错误（后台运行日志场景，默认 zh）
- 测试仅 3 处 `.Message` 断言（"name"、"command"、"nope" 标识符），双语均包含，无需改测试；实现时会再全量核对。
- WeComNotifier.cs 已是中文；SignalR/gRPC 无用户可见错误文案，不处理。
